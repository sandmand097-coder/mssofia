# mrsofia | Miss Sofia — مُدرِّسة العلوم

موقع **Miss Sofia — مُدرِّسة العلوم** بهوية مرئية عربية RTL مستقلة، ودورات علوم وفيزياء وأحياء وكيمياء، وصفحات التسجيل وتفاصيل الدورات، وثلاث لوحات منفصلة للطلاب والمعلمين والإدارة. المشروع يعمل محلياً ويحافظ على أنظمة الحجز والحصص والفصول المباشرة المعتمدة على LiveKit.

> الحالة الحالية: الموقع التعريفي يعمل للعامة على https://mssofia.pages.dev (Cloudflare Pages، بدون شاشة إيقاظ Render)، وربط LiveKit Cloud تم اختباره عبر بث حقيقي. **تسجيل الطلاب والدفع والحصص على بيانات الإنتاج ما زال معطلًا للأمان** حتى تفعيل PostgreSQL والبريد وإتمام سياسة الأطفال. استلام إيصال التحويل لا يفعّل الحجز تلقائيًا؛ الإدارة فقط توافق بعد التحقق من وصول المبلغ.

## Cloudflare Pages — واجهة سريعة لا تنتظر Render

الواجهة التعريفية منشورة حاليًا على **Cloudflare Pages** لتُقدَّم من CDN مستقل عن إيقاظ خادم Render المجاني. API وضع المعاينة (`/api/health` وتسجيل الحالة والكورسات العامة) يرد من Cloudflare Pages Functions مباشرة دون إيقاظ Render، فيما يبقى Render هو خادم التسجيل والحصص والمدفوعات **عند تفعيل الإنتاج بعد اختبارات الأمان**. يدعم البروكسي مرور جلسات HttpOnly من نفس الدومين مع منع التخزين المؤقت للبيانات الحساسة، وهو مغلق افتراضيًا. اقرأ `CLOUDFLARE-PAGES-RELEASE.md` للتفاصيل. **رابط Render القديم قد يستمر في إظهار صفحة الاستيقاظ**؛ استخدم https://mssofia.pages.dev لعرض المُدرِّسة. يوجد مسار تحديث GitHub Actions في `.github/workflows/cloudflare-pages.yml`، ويحتاج إضافة Cloudflare API Token محدود الصلاحيات مرة واحدة لتفعيل النشر التلقائي.

## لوحة الهوية الجديدة وطرق الدخول

- افتح الموقع بالضغط مرتين على `START-MRSOFIA.cmd` ثم اذهب إلى `http://127.0.0.1:5173`.
- الصفحات العامة: `/` و`/courses` و`/courses/:id` و`/login` و`/register`.
- لوحة الإدارة `/admin`، الطالب `/student`، المعلم `/teacher`؛ تسجيل الدخول يوجّه المستخدم تلقائياً للوحة دوره.
- صفحات Miss Sofia تحتوي على شعار مستقل وأيقونة متصفح وبيانات وصفية، وقائمة مواد علمية، وشرح طريقة التعلم وأسئلة شائعة.
- صور وفحوصات المتصفح: `mrsofia-hero-desktop.png` و`mrsofia-home-mobile.png` و`mrsofia-teacher-desktop.png`، والفحوصات في `qa-mrsofia.mjs` و`qa-teacher-mrsofia.mjs`.
- الدورات الحالية المعروضة في الاختبار تتضمن بيانات تجريبية تاريخية؛ لا تُعتبر منهجاً علمياً مُعتمداً باسم Miss Sofia، ويمكن إدارة المحتوى وتعديل أسماء المعلمين عبر الحسابات المعتمدة.
- **الدومين المجاني والنشر**: اقرأ `MRSOFIA-PUBLISHING.md`. يمكن لاحقًا ربط دومين خاص على Render. الرابط العام المفضل هو `https://mssofia.pages.dev`، أما `https://mssofia.onrender.com` فيظل عنوان خادم Render وقد ينام بسبب قيود الخطة المجانية. الوضع الكامل للـBackend يتطلب PostgreSQL دائمًا بدلًا من SQLite المحلي.

## الفصل الافتراضي للأطفال — أولوية المشروع

تدعم نسخة mrsofia الآن تصميم فصل فيديو مباشر شبيه بالفصول التفاعلية، مع واجهة مستقلة للمعلمة والطلاب. **تم تشغيل بث WebRTC محلي حقيقي على جهاز المشروع واختبار المعلمة والطالب في متصفحين**. عند توقف خادم LiveKit أو عدم توفر إعدادات البث، تظهر معاينة واضحة للفصل دون ادعاء أنه متصل.

- يبث حساب المعلمة الصوت والفيديو، ويمكنه مشاركة الشاشة مع صوت التبويب عند دعم المتصفح، ويشاهد الأطفال الدرس ويستمعون مباشرة.
- الوضع الافتراضي للطلاب: استقبال الصوت والفيديو فقط، دون صلاحيات تشغيل ميكروفون أو كاميرا.
- رفع اليد متاح للطلاب المقبولين؛ تظهر الطلبات في شاشة المعلمة.
- المعلمة تمنح إذن صوت أو كاميرا لطالب واحد في كل مرة، وتسحبه، وتغلق جميع الميكروفونات، وتستبعد الطالب وتُنهي الحصة للجميع.
- صلاحيات البث تُطبّق من الخادم عبر LiveKit AccessToken و RoomService API. لا يفتح ميكروفون الطالب أو كاميرته بدون نقرة منه وموافقة المتصفح.
- رسائل نصية من المعلمة إلى الجميع (دون دردشة مفتوحة للأطفال) مع زر معالجة التشغيل التلقائي للصوت.
- للتحكم في استخدام الموارد يسمح الخادم حاليًا بحد أقصى ست مشاركات صوتية للطلاب في الوقت نفسه.
- التحميل على آلاف المشاركين **غير مختبر**، والخدمة تحتاج استضافة LiveKit SFU حقيقية واختبار أعداد متزامنة قبل النشر العام. السعة البرمجية للدورة لا تضمن سعة البث.

راجع `LIVEKIT-SETUP.md` لربط LiveKit و`CLASSROOM-SCALING.md` لخطة اختبار استيعاب المئات و`MRSOFIA-PUBLISHING.md` للخصوصية والمتطلبات التشغيلية. اختبارا `tests/integration.mjs` و`tests/classroom-moderation.mjs` يستخدمان قواعد بيانات معزولة؛ الثاني يختبر الـmoderation عبر خادم LiveKit RPC محلي وهمي. معاينة واجهة الفصل: `node qa-classroom-mrsofia.mjs`.

## المزايا المنفذة

- الطالب: تسجيل بريد إلكتروني مع تأكيد برسالة، واستعادة كلمة المرور، وطلب حجز بعد التفعيل، ومتابعة حالة الموافقة، وعرض الجدول والدخول لغرفة الدرس في الموعد المحدد.
- المعلمة/المديرة: إنشاء حساب الموظفين يتم إداريًا فقط، وحساب Miss Sofia الإداري يقدر يبث مباشرة وينشئ كورسات باسمها ويوافق أو يرفض طلبات الطلاب.
- الإدارة: الموافقة على المعلمين أو إيقاف حساباتهم، إدارة الحجوزات وإنشاء الدورات وتعيين مدرس معتمد لها، وعرض سجل الحضور.
- إدارة المحتوى: تعديل بيانات الدورات من لوحة المدرس/الإدارة، وإعادة جدولة الحصص المستقبلية؛ يمنع الخادم المدرس من تعديل محتوى الآخرين ويمنع تقليل المقاعد تحت عدد الطلاب الموافق عليهم. لا يمكن إعادة جدولة حصة بدأت بالفعل.
- الحصص المباشرة: صوت، فيديو، مشاركة شاشة، ومحادثة لحظية داخل غرفة LiveKit؛ الطلاب المقبولون فقط يحصلون على رمز دخول مرتبط بالحصة.
- الحضور: يتم تسجيل الحضور عند وصول **إشعار مشارك متصل** موقّع من LiveKit، وليس عند طلب رابط أو رمز دخول. شاشة حضور مع مرشحات وتصدير CSV.
- واجهة عربية بالكامل ومتجاوبة، وكلمات المرور محفوظة على هيئة bcrypt hashes وجلسة في HttpOnly Cookie.

## إجراءات إطلاق المُدرِّسة والبريد والبيانات السحابية

راجع `SCHOOL-LAUNCH.md` لخطة حساب المُدرِّسة، تسجيل الطالب، التحقق بالبريد، ونشر Render + Supabase + LiveKit Cloud. البريد المحلي يظهر في ملفات معاينة ولا يصل إلى Gmail حتى تفعيل Resend/SMTP. تم إنشاء جداول Supabase والموقع التعريفي منشور؛ لم يكتمل بعد اتصال PostgreSQL الإنتاجي أو تفعيل البريد الحقيقي. أضيف تسجيل دخول Google للمديرة **اختياريًا ومغلقًا افتراضيًا**، ويُفتح بعد إعداد Google Cloud OAuth Client واعتماد بريد Admin موجود مسبقًا في القاعدة.

## التشغيل على Windows

المتطلبات: Node.js 24.x و npm (انظر engines في package.json).

افتح PowerShell في مجلد المشروع ونفّذ:

```powershell
npm ci
# نفّذ الأمر التالي مرة واحدة فقط إذا لم يوجد ملف .env:
node setup-local.mjs
npm run seed:demo
npm run dev
```

افتح **http://127.0.0.1:5173** من نفس الكمبيوتر. الخادم المحلي API على **http://127.0.0.1:4010**. بعد الإعداد الأول انقر مرتين على **START-MRSOFIA.cmd** لتشغيل واجهة Miss Sofia وفتحها؛ ملف التشغيل القديم يظل متاحاً للتوافق فقط.

**مهم:** ملفا `.env` و `LOCAL_ACCESS.txt` يحتويان بيانات حساسة؛ لم يتم تصميمهما للنشر. يتسبب تشغيل `node setup-local.mjs` مجدداً في توليد كلمات مرور ومفاتيح جديدة، لذا لا تعِد تشغيله على قاعدة بيانات مستخدمة دون أخذ نسخة احتياطية والتأكد من خطة التدوير.

الحسابات التجريبية محلياً (عناوين البريد فقط، كلمات المرور محفوظة محلياً في `LOCAL_ACCESS.txt`):

- الإدارة: `admin@madrasati.local`
- المدرس: `teacher@madrasati.local`
- الطالب: `student@madrasati.local`

لإنشاء حساب مدرس جديد استخدم الإدارة الداخلية أو دعوة خاصة، ولا يمكن لأي زائر منح نفسه دور مدرس. لتجربة التسجيل وتفعيل البريد وموافقة المديرة افتح `SCHOOL-LAUNCH.md` ثم شغّل `node qa-registration-admin.mjs` (قاعدة اختبار معزولة).

## تفعيل البث الحقيقي (LiveKit)

يوصى بـ **LiveKit Cloud** كبداية. تنشئ مشروعاً خاصاً لدى المزود وتحصل على:

```dotenv
LIVEKIT_URL=wss://YOUR-LIVEKIT-HOST
LIVEKIT_API_KEY=YOUR_API_KEY
LIVEKIT_API_SECRET=YOUR_API_SECRET
```

ضع القيم في `.env` على خادم الموقع **فقط**، ثم أعد تشغيل الخادم. لا تنقل `LIVEKIT_API_SECRET` إلى React ولا إلى Git أو صفحة عامة.

في إعدادات LiveKit قم بتوجيه Webhook إلى عنوان عام آمن HTTPS:

```text
https://YOUR-WEBSITE-DOMAIN/api/webhooks/livekit
```

الـWebhook يعالج الحدث `participant_joined` ويتحقق من توقيعه قبل كتابة سجل الحضور. **في التشغيل المحلي بدون عنوان عام لا تصل إشعارات LiveKit إلى localhost**؛ لذلك لا يظهر حضور فعلي في السجل حتى تجهز عنوان ويبهوك يمكن الوصول إليه. لا يلزم تفعيل webhook لمجرد تجربة البحث والحجز والدروس.

يفضل المدرس والطالب استخدام المتصفح الحديث مع كاميرا/مايكروفون عبر HTTPS. يبدأ العميل والكاميرا والمايكروفون مغلقان افتراضياً، ويمكن تفعيلهما من أزرار الاجتماع. تتيح واجهة VideoConference أيضاً مشاركة الشاشة والمحادثة داخل الحصة. البث الفعلي غير قابل للاختبار طرفاً لطرف دون حساب LiveKit صالح واتصال جهازين.

## الفحص والتشغيل الإنتاجي

```powershell
npm run check
npm test
npm run build
npm start
```

- `npm test` يشغل اختبارات API وتفويض المستخدمين والحجوزات والتوكنات والويبهوك على قاعدة SQLite مؤقتة؛ لا يعدّل بياناتك الحقيقية.
- `npm run build` ينشئ الواجهة داخل `dist/`.
- `npm start` يقدم الملفات المُنشأة والـAPI من الخادم المحلي في المنفذ 4010.
- `MADRASATI_DB_PATH` متغير اختياري لتحديد مكان قاعدة البيانات في بيئة الاختبار، وإلا تستخدم `data/education.sqlite`.
- فحوصات أخطاء البناء لا تعني ضمان الأداء أو الحماية لجميع أحمال التشغيل.

## تعليمات مهمة قبل الإطلاق للعامة

1. استضف الموقع والخادم خلف HTTPS مع نطاق موثوق، وغيّر `NODE_ENV=production` و`APP_ORIGIN=https://YOUR-DOMAIN` واضبط إعدادات الاستضافة والعكس الوكيل (reverse proxy) ومخازن الأسرار بشكل آمن.
2. استعمل بيانات اعتماد قوية وحصرية، لا تستخدم الحسابات التجريبية في الإنتاج، وفعل نسخاً احتياطية دورية من قاعدة البيانات.
3. لعدد كبير من الطلاب استخدم PostgreSQL مُداراً بدلاً من الاعتماد على SQLite كقاعدة بيانات للتوسع؛ وضع خطط السعة وتكلفة وسائط LiveKit حسب عدد الحضور المتزامنين.
4. أضف سياسات الخصوصية وحماية القُصّر وموافقة ولي الأمر وإدارة المحتوى، وراجع متطلبات بلد النشر قبل جمع بيانات أطفال.
5. **لا توجد حالياً بوابة دفع أو فواتير أو استعادة كلمة المرور عبر البريد أو رسائل تذكير أو تسجيل حصص إلى مكتبة فيديو**. الأسعار المعروضة معلوماتية، وإن وُجدت رسوم فتنسيق الدفع خارج المنصة حتى إضافة نظام آمن.
6. خزّن بيانات الوصول والنسخ الاحتياطية بعيداً عن Git، واختبر الاتصال وتسجيل الحضور مع حساب LiveKit فعلي قبل التسليم التجاري.

## البنية التقنية

- Frontend: React 19 + Vite + react-router-dom + Lucide Icons + Cairo font.
- Backend: Express 5، جلسات JWT في HttpOnly Cookie، bcryptjs، rate limiting وsecurity headers.
- Database: SQLite باستخدام `node:sqlite`، مع جداول users / courses / lessons / bookings / attendance.
- Video: LiveKit JS Server SDK و React VideoConference، وتوكنات دخول يصدرها الخادم بعد التحقق من الدور والحجز والموعد.
- `src/components/Classroom.jsx`: واجهة غرفة الفيديو.
- `src/components/AttendancePanel.jsx`: عرض وتصدير سجل الحضور.
- `tests/integration.mjs`: اختبارات عمليات API والصلاحيات.
